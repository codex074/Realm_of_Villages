## Public functions
- `ranking.get_ranking(s, world_id, cfg) -> list[RankingRow]`
  One row per player. Population = sum of `pop_per_level*level` over ALL building rows of the
  player's villages, loaded with a single joined query (Village ⋈ Building). Sorted by
  population desc, villages desc, player id asc; rank = 1-based position.
- `villages.handle_starvation(s, village_id, now, cfg) -> None`
  Locks the village (silently returns when missing), settles it, computes rates. Starving only
  when `food <= 1e-6` and food rate < 0. Kills home-village troops first (then away troops),
  highest `cfg.units[unit].upkeep` first within each group (ties: unit key, row id), using
  `math.ceil(remaining_deficit / (upkeep * speed))` per row, stopping once the deficit <= 1e-9.
  Moving Movement units are never killed. On kills: an 'info' report "ทหารอดอาหารตาย" + notify.
  Afterwards: if the food rate is now >= 0 -> `after_change`; if still negative -> cancel the
  village's pending STARVATION_CHECK events (no endless chain) and leave food at 0.
- `worlds.end_round(s, world_id, now, cfg) -> None`
  Idempotent (returns when world missing or status != 'running'). Crowns the top-ranked player,
  sets `status='ended'` and `winner_player_id`, writes one 'info' report per player (bots too)
  with the winner summary, top-10 and `your_rank`, and notifies everyone with kind 'round_end'.
- `engine.handlers.handle_starvation_check` / `handle_round_end`

## Key design decisions / limits
- **Event finalisation in the handler:** `after_change` calls `events.cancel_pending`, which
  deletes *all* pending STARVATION_CHECK events for the village — including the one the worker is
  currently processing. To keep the worker's contract that every processed event ends `done`
  (matching the other handlers), `handle_starvation_check` sets `ev.status = "done"` and flushes
  **before** running the logic, so `cancel_pending` (pending-only) no longer deletes the live row.
- `handle_starvation` uses a raw `SELECT ... FOR UPDATE` (not `lock_village`) so a missing village
  returns silently instead of raising NOT_FOUND (required by the pre-existing
  `tests/engine/test_worker.py::test_noop_handlers`, which schedules a check for a non-existent id).
- Deficit math uses `math.ceil` on floats with a `1e-9` guard against float noise.
- `ranking.py` imports nothing from worlds/villages (no circular imports).
