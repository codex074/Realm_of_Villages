# T07b handoff: web app shell (app.js, dom.js, newgame view)

## What was done
Built the frontend app shell: safe DOM builder, hash router + top bar + bottom nav +
toasts + refresh logic in `app.js`, and the new-world form view. Vanilla ES modules,
no libraries, no `innerHTML` anywhere. All user-visible strings are Thai.

## Files
- `web/js/dom.js` — `h(tag, attrs, ...children)` and `clear(el)`. Attr handling:
  `class` -> className, `style` object -> Object.assign(el.style), `dataset` object,
  `on*` function -> addEventListener (lowercased, 'on' stripped), boolean attrs
  (disabled/hidden/checked/selected/readonly/required/multiple/autofocus/open) set as
  properties, everything else setAttribute. Children: strings/numbers appended as text
  nodes (never HTML), Nodes appended, arrays flattened, null/false/undefined skipped.
- `web/js/app.js` — the app shell:
  - Init: `GET /meta`, then `GET /state`; on `ApiError` status 404 -> `#/new`.
    Otherwise `syncClock(state.game_now)`, pick current village (first of
    `state.villages`, or the one in the route), `GET /villages/{id}`.
  - Hash router: `#/new` -> newgame, `#/` & `#/v/:id` -> village, `#/v/:id/center` &
    `#/center` -> center, `#/map` -> map, `#/reports` & `#/reports/:id` -> reports,
    `#/ranking` -> ranking, `#/rally/:vid` -> rally. View modules loaded with dynamic
    `import('./views/<name>.js')`; a failed import shows a panel with
    'หน้านี้ยังไม่พร้อมใช้งาน'. Unknown hash -> `#/`. Params `{id, vid}` plus `query`
    (URLSearchParams of the hash query string) are passed to `render(el, ctx, params)`.
  - View contract: views export `async render(el, ctx, params)`, may return a cleanup
    function called before the next route renders. `ctx` = { meta, state, village,
    villageId, toast, refresh, navigate }.
  - Top bar: `#res-wood/stone/iron/food` tick every 1 s:
    `resources[k] + rates[k] * elapsed game hours since village fetch` (game clock),
    clamped to `[0, capacity[k]]`, shown with `fmtNum`; food span gets `.negative` when
    `rates.food < 0`. `#clock` shows `fmtTime(gameNow().toISOString())` each second.
    `#pause-btn` label 'หยุด'/'เล่นต่อ' from `state.paused`; click ->
    `POST /admin/pause` or `/admin/resume`, then updates state + clock.
    `#village-select` lists `state.villages` (option text = name), navigates to
    `#/v/<id>` on change, hidden when there is only one village.
  - Bottom nav: link hrefs rewritten to `#/v/<id>`, `#/v/<id>/center`, `#/map`,
    `#/reports`, `#/ranking` once the village id is known; `.active` on the link
    matching the current hash.
  - Countdowns: every `<span class="countdown" data-countdown="ISO">` in `#view` is
    updated each second with `countdown(iso)`; when any reaches 0 (`remainingMs == 0`)
    ONE debounced `ctx.refresh()` is scheduled 1.5 s later.
  - ws: `onChanged` -> if `village_id` is null or equals the current village id,
    debounce 300 ms then `ctx.refresh()`.
  - `ctx.toast`: text in `#toast` for 4 s, `.toast-error` for errors, a new toast
    replaces the old one.
  - `ctx.refresh`: refetches state (and the current village when selected), then
    re-renders the current route; guarded by an `inflight` flag with one queued
    follow-up (no parallel recursive refresh); skips the render round while the user
    is typing in an input/select/textarea inside `#view` and retries after 1 s.
  - Any `ApiError` during render/refresh is shown with `ctx.toast(message, true)`;
    the route never crashes.
- `web/js/views/newgame.js` — route `#/new`: 'Realm of Villages' heading + short Thai
  subtitle; form with player name input (default 'ผู้เล่น', required), tribe radio
  cards from `ctx.meta.tribes` (name_th + description_th, first selected), speed
  `<select>` from `ctx.meta.speeds` (labels x1/x3/x5/x10), bot count 0-60 (default 30),
  optional seed number input. Submit -> `POST /admin/new-world`
  `{player_name, tribe, speed, bot_count, seed}` (seed null when empty); button
  disabled while waiting; on success toast 'สร้างโลกแล้ว', `location.hash = '#/'`
  then `await ctx.refresh()`; on `ApiError` toast the message and re-enable the button.
- `web/css/style.css` — appended a final section `/* app shell + newgame */` only:
  `.newgame`, `.newgame-title`, `.newgame-subtitle`, `.newgame-form`, `.form-row`,
  `.form-row-inline`, `.form-label`, `.tribe-cards`, `.tribe-card`,
  `.tribe-card.selected`, `.tribe-name`, `.tribe-desc`, plus small app-shell helpers
  (`#village-select[hidden]`, `#pause-btn` sizing). Existing rules untouched.

## Public functions
- dom.js: `h(tag, attrs, ...children)`, `clear(el)`
- app.js: no exports (entry module; builds `ctx` and starts tickers/router)
- views/newgame.js: `render(el, ctx, params)` (view contract)

## Limits / notes
- `views/village.js`, `center.js`, `map.js`, `reports.js`, `ranking.js`, `rally.js`
  do not exist yet; their routes show the 'หน้านี้ยังไม่พร้อมใช้งาน' panel until
  those tasks land (dynamic import failure is handled).
- `ctx` is exposed to views only as an object literal (no module export); views must
  use `ctx.meta/state/village/villageId/toast/refresh/navigate` per the contract.
- Resource ticker uses the game clock (`gameNow()`) for elapsed time, so pausing the
  world freezes the displayed resources as well.
- `#clock` shows '' until the first successful `/state` fetch.
- The 1 s tickers start before the initial fetch; they are no-ops until state/village
  exist, so the `#/new` -> world-created flow also gets working tickers.
