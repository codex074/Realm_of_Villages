# T23b — Oasis: attack/capture, production bonus, conquest release, map info

## What was done
Oases can now be attacked and raided. A winning ATTACK captures the oasis for the
attacker village (up to `cfg.oasis.max_per_village`), a winning RAID only thins the
defending wild animals. Each owned oasis gives its village a `cfg.oasis.bonus`
production multiplier on the oasis resource (bonuses add up). Conquering a village
frees the oases it owned. The map view reports per-oasis info.

## Files changed
- `realm/services/oasis.py` (NEW) — all new oasis logic:
  - `is_oasis_tile(s, world, tx, ty) -> bool`
  - `owned_oases(s, village_id) -> int`
  - `oasis_send_problem(s, player_id, village, world, tx, ty, mission, cfg) -> tuple[str, str] | None`
    (radius / own-oasis / capacity checks, in that order)
  - `resolve_oasis_arrival(s, m, world, now, cfg) -> bool` — the battle/capture
    handler; returns False when the target tile is not an oasis (so the old
    "no village -> return trip" path still runs).
- `realm/services/military.py` (small edits):
  - `_check_send`: for ATTACK/RAID with no village on the target tile, an oasis
    tile is a valid target subject to `oasis.oasis_send_problem`; SCOUT/REINFORCE
    keep the old INVALID_TARGET. `to_village_id` stays None; protection rules do
    not apply to oases.
  - `_resolve_battle_arrival`: 2-line hook at the top — when `m.to_village_id is
    None` and `oasis.resolve_oasis_arrival(...)` returns True, return immediately.
- `realm/services/villages.py` (small edit): `compute_rates` scales each resource's
  gross production by `(1 + cfg.oasis.bonus * n_t)` where `n_t` is the count of
  oases of that resource owned by the village (before upkeep).
- `realm/services/conquest.py` (small edit): `conquer_village` sets
  `oasis_owner_village_id = NULL` on oases owned by the conquered village (after
  the culture settle, before the owner change).
- `realm/services/views.py` (small edit): `MapTile` gains a last field
  `oasis: dict | None = None`.
- `realm/services/worlds.py` (small edit): `get_map` fills `oasis` for kind
  'oasis' tiles with `{'owner_village_id', 'owned_by_me', 'animals'}` (None for
  other tiles).
- `tests/services/test_oasis.py` (NEW) — 13 DB tests, hand-computed.
- `tests/services/__init__.py` (NEW, empty) — see "Note on test layout".

## Tests (hand-computed, speed 1, human tribe stonehold)
- ATTACK 30 swordsmen on a 10-rat oasis: A=1200, D=260, attacker loses 3, all 10
  rats die, oasis captured, return `{'swordsman': 27}`, title ยึดโอเอซิสสำเร็จ,
  `data.oasis.captured True`.
- Production: 1 wood oasis -> wood rate 8*1.25=10; 2 wood oases -> 8*1.5=12;
  stone/iron/food unchanged.
- RAID 30 swordsmen: attacker loses 3, defenders lose 9 -> `{'rat': 1}` remain,
  no capture, return `{'swordsman': 27}`, title ปล้นโอเอซิส.
- Failed ATTACK 5 swordsmen (A=200 < D=260): all 5 lost, no return, rats lose 7
  -> `{'rat': 3}`, no capture, `attacker_won False`.
- Capacity (3 owned): ATTACK at a 4th -> INVALID_TARGET โอเอซิสเต็มจำนวนแล้ว; RAID allowed.
- Radius (distance 5): INVALID_TARGET โอเอซิสอยู่ไกลเกินไป.
- Own oasis: INVALID_TARGET โอเอซิสเป็นของคุณแล้ว.
- SCOUT at an oasis: INVALID_TARGET (old behaviour).
- Steal a bot-owned oasis: transfer to A, bot gets info report โอเอซิสของคุณถูกยึด,
  bot's wood bonus drops.
- Conquest of the owning village frees its oases (owner None).
- Integration: `send_troops` then `engine.worker.process_next` runs the battle.
- `get_map` around (0,0) r=3: oasis tile oasis dict before/after capture;
  non-oasis tiles `oasis is None`.
- Attack at a plain valley (no village, no oasis) still returns the units.

## Note on test layout
`tests/core/test_oasis.py` (T23a) and the required `tests/services/test_oasis.py`
share a basename and neither directory had an `__init__.py`, which makes pytest's
default (rootdir/import-mode) collection fail with an import-file mismatch.
`tests/bot` already carries an `__init__.py` for the same reason (its
`test_worker.py` collides with `tests/engine/test_worker.py`). I added an empty
`tests/services/__init__.py` so `tests.services.test_oasis` is a distinct module.
This is the minimal change that keeps both test files collectable; no test was
renamed or skipped.
