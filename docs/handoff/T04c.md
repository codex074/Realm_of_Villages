## Public functions
- `lock_village(s, village_id) -> Village` — `SELECT ... FOR UPDATE`; `NOT_FOUND` when missing.
- `levels(s, village_id) -> dict[str, int]` — highest level per building type.
- `compute_rates(s, village, now, cfg) -> tuple[Res, Res]` — net rates (fields at speed and
  player production mult, population from ALL building rows, upkeep from home Troop rows of any
  location plus units of outgoing `moving` Movements) and capacity from warehouse/granary levels.
- `settle_village(s, village, now, cfg) -> None` — no-op when `now <= res_updated_at`; else
  `economy.settle` and write back stock + `res_updated_at = now`.
- `settle_player_culture(s, player, now, cfg) -> None` — accrues `culture_per_day * elapsed_days`
  over all the player's buildings; no-op when `now <= cp_updated_at`.
- `after_change(s, village, now, cfg) -> None` — cancels pending `STARVATION_CHECK` for the
  village; reschedules it at `now + seconds_until_food_empty` when the food rate is negative.
- `build(s, player_id, village_id, slot, btype, now, cfg) -> BuildQueue` — order: lock →
  owner check → settle → `slot_accepts` (and unknown btype) → no duplicate center building/queue
  in another slot → max level → requirements → queue limit → slot not already in queue →
  deduct cost → insert BuildQueue → schedule `BUILD_COMPLETE` (payload `{'build_queue_id': id}`,
  `due_at == finishes_at`, back-referenced via `event_id`) → `after_change` → `notify`.
- `complete_build(s, build_queue_id, now, cfg) -> None` — idempotent (missing id returns);
  lock → settle BEFORE the level change → upsert Building row → delete queue row →
  `after_change` → `notify`.
- `rename_village(s, player_id, village_id, name, now, cfg) -> None` — owner check, strip,
  1..40 chars else `INVALID_TARGET`.

## Behavior / decisions
- Population is computed from the list of (type, level) pairs of EVERY building row (per lead),
  not from `levels()`; `compute_rates` still uses `levels()` for warehouse/granary capacity.
- `now` is unused in `compute_rates` but kept in the signature per the contract.
- Thai error messages are the short strings from the lead's list (single tone mark, no typos).
- Never commits; never calls `datetime.now()`; all numbers come from `cfg`.

## Tests
Fresh-village rates 8/8/8/10 and capacity 800; build woodcutter slot 1 (cost 50/90/40/50,
240 s, one queue row + one pending BUILD_COMPLETE with matching payload/due_at/event_id);
second build → QUEUE_FULL (also for the busy slot); wood=0 → INSUFFICIENT_RESOURCES with no
side effects; barracks slot 20 → REQUIREMENTS_NOT_MET; farm on slot 1 → INVALID_SLOT;
farm at level 15 → MAX_LEVEL; second warehouse in another center slot → INVALID_SLOT;
other player → FORBIDDEN; unknown village → NOT_FOUND; complete_build at t0+240 s settles at
old rates (700+8·240/3600 wood, 700+10·240/3600 food), applies level 1, gives 16 wood / 9 food
rates, and is a no-op when repeated; settle growth + capacity cap + no-op for earlier `now`;
troop/movement upkeep (10 home spearmans, 5 moving, 0 for done); after_change schedules exactly
one STARVATION_CHECK at t0+270000 s, does not duplicate, and cancels when rate >= 0;
culture accrual 2/day; rename trim/empty/too-long/FORBIDDEN.
