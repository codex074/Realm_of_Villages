## Public functions
- `TileSpec(x, y, kind: TileKind, layout: str | None, oasis_type: str | None)` — frozen dataclass.
- `generate_tiles(seed: int, cfg: GameConfig) -> list[TileSpec]` — full 101×101 tile map,
  deterministic from `seed`. Iterates x outer / y inner over -50..50. Kind chosen with
  `rng.choices` over `cfg.world.tile_weights` (YAML order); valley gets a layout, oasis gets
  `oasis_type` from `RESOURCE_KEYS`, mountain/lake get `None`. Tile (0,0) is force-overwritten
  to valley `4-4-4-6` after generation (does not disturb the rng sequence).
- `pick_spawns(tiles, seed, bot_radius_mins, cfg) -> tuple[tuple[int,int], list[tuple[int,int]]]`
  — player = valley closest to (0,0) (tie: smallest (x,y)); bots placed in order using
  `random.Random(f"{seed}:spawns")` over a single shuffle of the (x,y)-sorted valley list.
  Each bot must satisfy `radius_min <= dist((0,0)) <= bot_spawn_max_radius` and
  `dist >= min_village_distance` to every already-placed village. If none matches, the max
  radius is widened by 5 until it exceeds the half-size, then `ValueError` is raised.

## Design notes / limits
- Torus distance helper `_torus_distance` is private to this module (no `movement` import).
- Pure functions: no DB, no clock, only `random.Random` seeded from the given seed.
- `pick_spawns` is fast in the common case (single shuffle, first-fit scan per bot).

## Tests
9 tests, all passing: grid coverage (10201 unique coords), determinism + seed sensitivity,
center tile, per-kind field consistency, proportions within 2pp of weights (70/4/1/10/10/3/2),
spawn constraints (player (0,0), 30 distinct valley bots, pairwise torus distance >= 3,
per-bot radius bounds, radius-15 bots >= 15 from player), spawn determinism, ValueError on an
unsatisfiable tiny tile list, and a <2s performance bound.
