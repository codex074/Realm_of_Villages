# T20a — culture points, settle mission (send + arrival), state culture fields

## What was done
Implemented culture points and founding new villages (Phase 2 / T20) following the lead's design.

### `realm/services/villages.py`
- `projected_culture(s, player, now, cfg) -> float` — read-only projection:
  `player.culture_points + economy.culture_per_day(all (type, level) building rows of all the
  player's villages, world.speed, cfg) * elapsed_days`, with `elapsed_days = max(0, (now -
  cp_updated_at)/86400)`. No writes.
- `settle_player_culture(s, player, now, cfg)` — reimplemented on top of `projected_culture`;
  writes `culture_points = projected_culture(...)` and `cp_updated_at = now` only when
  `now > cp_updated_at`. Signature and existing test behaviour unchanged.
- `culture_needed_for_next_village(s, player, cfg, extra_pending=0) -> float | None` —
  `owned = #player villages + extra_pending`; returns `cfg.culture.village_cp_thresholds[owned]`
  or `None` when `owned >= len(thresholds)`.
- `complete_build` — now calls `settle_player_culture` for the village owner right after
  `settle_village` and BEFORE the building level changes, so culture accrues with the old levels.

### `realm/services/military.py`
- Removed the unconditional `SETTLE_NOT_READY` problem (and the `SETTLE_NOT_READY_TH` constant).
- `_check_send` — for `SETTLE`, after the rally-point and unit validation, the same-tile-as-sender
  check keeps its existing message; otherwise (a) the target tile must exist in `tiles` with
  `kind == 'valley'` and have no village on it, else `(INVALID_TARGET, 'ช่องน้ีตั้้งหมู่บ่านไม่ได้')`;
  (b) `pending = #player movements with mission 'settle' and status 'moving'`,
  `need = villages.culture_needed_for_next_village(s, player, cfg, extra_pending=pending)`,
  `points = villages.projected_culture(s, player, now, cfg)`; `need is None or points < need`
  -> `(NOT_ENOUGH_CULTURE, 'แต้มวัฒนธรรมไม่พอ')`. Troop-availability check and the rest unchanged.
- `send_troops` — for `SETTLE` it additionally calls `villages.settle_player_culture(s, player,
  now, cfg)` after the checks pass. Settle movements keep `to_village_id = None` and have no
  protection effects. `preview_send` reports the same problems as errors and never writes.
- `resolve_arrival` — new dispatch branch `mission == 'settle'` -> `_resolve_settle_arrival`.
- `_resolve_settle_arrival(s, m, world, now, cfg)` — locks the home village (`m.from_village_id`)
  and settles it + `settle_player_culture(now)`. Success only when the tile at `(to_x, to_y)` is
  still `kind 'valley'`, still has no village, and `projected culture >=
  culture_needed_for_next_village(s, player, cfg)` (extra_pending 0: the movement is being
  resolved so it is no longer counted). On success: creates the new `Village`
  (name `f'บ่านของ{player.name} {owned + 1}'`, x/y of the tile, `layout = tile.layout`,
  `is_capital False`, `loyalty 100`, resources 0/0/0/0, `res_updated_at = created_at = now`)
  and its `Building` rows from `slots.initial_buildings(layout, cfg)`; settlers are consumed (no
  troops, no return trip); a `'settle'` report titled 'ตั้้งหมู่บ่านใหม่สำเร็จ' with
  `data {'village': {'id','name','x','y'}}`; `after_change` for the new village; notify. On
  failure: `create_return_movement(...)` plus a `'settle'` report titled
  'ตั้้งหมู่บ่านใหม่ไม่สำเร็จ' with `data {'reason': 'tile'|'culture', 'x', 'y'}`. Both paths set
  `m.status = 'done'`.

### `realm/api/routes/state.py`
- `build_state` adds to the `player` dict: `'culture_points'` (`projected_culture` rounded to 2
  decimals) and `'culture_next'` (`culture_needed_for_next_village`, or null).

## Limits / notes
- Culture accrues from every building with `cp_per_level * level > 0`, including `rally_point`
  and `wall` (both `cp_per_level: 1`). A fresh capital therefore accrues 2 CP/day (town hall
  level 1 only); the test culture tests keep the rally point at level 0 to match the hand-computed
  expectations, while the send/arrival tests upgrade it to level 1 (required to send).
- The tile/culture re-check on arrival uses the *settled* `player.culture_points` (equivalent to
  `projected_culture` at `now` because `settle_player_culture` runs first).
- Only the home village is locked on settle arrival (single-village lock order rule).
