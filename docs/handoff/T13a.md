# T13a — military: send_troops, preview_send, recall_reinforcement, return arrival

## What was done
Implemented `realm/services/military.py` for the "send troops" half of T13, following the
lead's design exactly:

- `send_troops` — validates a send, deducts home troops, creates the `Movement`, schedules a
  `MOVEMENT_ARRIVE` event, re-settles the sender (`after_change`) and notifies both parties.
  A hostile send by a still-protected attacker drops `player.protection_until` to `now`.
- `preview_send` — same checks but read-only (no row locks, no settle, no protection change);
  returns a `SendPreview` with distance / travel_time_s / arrive_at / carry and the full list
  of Thai error messages (NOT_FOUND / FORBIDDEN still raise, as they are ownership errors).
- `recall_reinforcement` — turns a reinforcement `Troop` (home != location) back into a
  `return` movement; locks both villages in ascending-id order and settles both.
- `create_return_movement` — builds a `mission='return'` movement (home village stored in
  `from_village_id`, origin in `to_x/to_y`, `to_village_id=None`) and schedules its arrival.
- `resolve_arrival` — fully handles the `return` mission (upsert home troops, add loot with
  capacity clamp, mark `done`, re-settle + notify). Every other mission raises
  `NotImplementedError('T13b')`. A `done`/missing movement is a no-op.

Shared private helper `_check_send(..., lock: bool)` returns a context plus the ordered list of
`(code, thai_message)` problems. Check order: lock -> owner (FORBIDDEN) -> settle -> RETURN ->
SETTLE -> rally_point>=1 -> validate_mission_units -> catapult_target -> self-tile -> hostile
target (empty / same-player / protected) -> reinforce target -> not-enough-troops.

Thai strings are limited to the proofread ones from the design plus the reused
`villages.FORBIDDEN_TH` / `VILLAGE_NOT_FOUND_TH`. No `datetime.now()`, no hard-coded numbers
(all read from `cfg`), no new dependencies. `realm/core` is untouched.

## Limits / notes
- Only the `return` mission is resolved; attack / raid / scout / reinforce / settle arrivals
  are T13b (`NotImplementedError('T13b')`).
- `resolve_arrival` for `return` clamps loot to capacity using `villages.compute_rates`;
  excess is dropped (per spec).
- `realm/engine/worker.py` (`process_next`) is intentionally NOT touched in this task.
- `villages.get_village_view` still does not surface `movements`/`troops_away`/
  `reinforcements_here` additions requested in the T13 header — that is a separate T13b/views
  change, out of scope here.
