# T06b handoff — api: websocket + lifespan listener, cli api/new-world/pause/resume

## What was done
- `realm/api/ws.py` (new): WebSocket endpoint `/ws` (ping→pong), `Hub` broadcast registry,
  and `listen_loop()` that connects to PostgreSQL via `psycopg.AsyncConnection`,
  runs `LISTEN game_events`, filters notifications by human players of the world
  (cached per world id, sync query via `asyncio.to_thread` + `session_scope`),
  broadcasts `{"type": "changed", "kind": ..., "village_id": ...}` to all sockets,
  and reconnects after 2 s on any non-cancellation error.
- `realm/api/main.py`: added a FastAPI `lifespan` async context manager that starts
  `asyncio.create_task(ws.listen_loop())` on startup and cancels+awaits it on shutdown
  (ignoring `CancelledError`). `ws.router` is included with no prefix BEFORE the static
  mount. Everything else unchanged.
- `realm/cli.py`: implemented `api` (uvicorn factory run, lazy import), `new-world`
  (--speed/--name/--tribe/--bots/--seed; random seed when omitted; echoes
  `world <id> created (speed=..., seed=...)`), `pause` and `resume` (echo `paused`/`resumed`).
  `session_scope` is imported at module level so tests can monkeypatch `realm.cli.session_scope`.
  `migrate`, `engine`, `bots`, `simulate` unchanged.
- `tests/api/test_ws_cli.py` (new): psycopg_dsn, message_for (human/bots/bad-JSON/None
  village_id), ping→pong via TestClient without lifespan, Hub.broadcast with fake/bad
  sockets, lifespan start/cancel via monkeypatched `ws.listen_loop`, CLI
  new-world/pause/resume with a patched `session_scope` yielding the `s` fixture,
  and `--help` listing all 8 commands.

## Limits / notes
- The human-id cache in `listen_loop` is never invalidated; stale ids only matter if
  players are deleted mid-world (worlds are single-player human + bots, so this is fine
  for Phase 1).
- `listen_loop` parses the payload twice (once for world_id, once inside `message_for`);
  acceptable for clarity.
- Phase 1 broadcasts to every connected client (single human player), as per spec.
