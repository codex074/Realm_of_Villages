# T24a — bot: expand module (train settlers, found new villages)

## What was done
Added the `expand` bot module (T24 part a). A bot may found a new village when it
has enough projected culture for the next village (counting already-moving settle
movements as pending). When it already has the required settlers at home it sends
them to the best empty valley tile; otherwise it queues settler training if the
requirements, queue and stock allow it.

## Files
- `realm/bot/action.py` — added `settle` kind to `Action.execute` (calls
  `military.send_troops(..., Mission.SETTLE, ...)`); updated the kind comment.
- `realm/bot/modules.py` — added `expand(ctx)` and `_find_settle_tile(ctx)`;

- `docs/handoff/T24a.md` — this file.

## Public functions
- `modules.expand(ctx: BotContext) -> list[Action]` — returns one `settle` action
  (score 4.0) when `settlers_needed` settlers are at home and a valid tile exists,
  else one `train` action (score 3.5) to train settlers, else `[]`.
- `modules._find_settle_tile(ctx) -> tuple[int, int] | None` — nearest empty valley
  within `personality.expand_radius` (torus distance, `1..radius`), excluding tiles
  that already hold a village, that are the destination of any moving settle
  movement, or closer than `cfg.world.min_village_distance` to any village. Uses
  one query each for tiles, villages and settle movements.

## Behaviour / limits
- Read-only: the module never mutates state; `Action.execute` mutates via services.
- Culture gate uses `villages.culture_needed_for_next_village` (with
  `extra_pending` = moving settle count) and `villages.projected_culture`.
- Settler availability for the train branch counts settlers with
  `home_village_id == village` (any location) plus settlers in the bot's moving
  settle movements.
- `settle` execution still goes through `military.send_troops`, which enforces
  rally_point, tile and culture rules server-side.
