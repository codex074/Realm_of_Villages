# T15b — web: map view + rally (send troops) view

## What was done
Implemented the two remaining views per BUILD.md §10, following the existing
`render(el, ctx, params)` view contract used by `village.js`.

## Files
- `web/js/views/map.js` (new)
- `web/js/views/rally.js` (new)
- `web/css/style.css` (appended a `/* map + rally */` section at the end only)

## Public functions
- `web/js/views/map.js` → `export async function render(el, ctx, params)`
  - Route `#/map?x=&y=`. Center from query x/y (integers) or the current
    village's `village.x/y`. Fetches `GET /map?cx=&cy=&r=7` (15x15 MapView).
  - Draws a 15x15 grid of 40px cells on a `<canvas>` (600x600, CSS 100% /
    max-width 600px / height auto). Tile colors: valley `#cfe3b4`, oasis
    `#7fbf6a`, mountain `#a08c74`, lake `#7fb2d9`; thin grid lines; villages
    as filled circles (blue `#1f5fbf` when `is_mine`, red `#c0392b` when
    `is_bot` and not mine); the center cell gets a darker outline.
  - Pointer drag pans: on release the drag distance is converted to whole
    tiles (`round(-delta / cellPixelSize)`) and it navigates to the new
    `#/map?x=&y=`. A click (< 5px movement) selects the cell under the
    pointer and fills an info `.panel` (พิกัด, tile type label, and when a
    village stands there: name / player / tribe name_th / population /
    ของคุณ-or-bot marker; otherwise ไม่มีหมู่บ้าน). The panel always has a
    primary ส่งทัพ button navigating to `#/rally/:vid?x=&y=` (hidden for the
    player's own village).
  - Controls above the canvas: four arrow buttons (±3 tiles) and x/y number
    inputs prefilled with the center plus a ไป button.
  - Returns a cleanup function that removes the canvas pointer listeners.
- `web/js/views/rally.js` → `export async function render(el, ctx, params)`
  - Route `#/rally/:vid?x=&y=`. Uses `ctx.village` (the village of :vid).
  - Unit rows for every `troops_home` entry with count > 0 (name_th +
    (มีย count) + number input min 0/max count/default 0 + ทั้งหมด button);
    shows ไม่มีทหารให้ส่ง when there are none.
  - Mission `<select>` (attack/raid/scout/reinforce, no settle), x/y number
    inputs prefilled from the query, and a catapult target `<select>`
    (สุม + one option per building whose kind is 'center') shown only when
    catapult is selected and the mission is attack.
  - Result `.panel` with a debounced (300ms) `POST /villages/:vid/send/preview`
    showing เวลาถิง / ใช้เวลา / ระยะทาง (1 decimal) / บรรทุกได้ and each error
    as a `.negative` line; skipped when no unit is selected or x/y empty.
  - Primary ส่ง button disabled when no unit, x/y empty, or last preview had
    errors; on click `POST /villages/:vid/send`, then toast ส่งทัพแล้ว and
    `await ctx.refresh()`; ApiError → toast(err.message, true).
  - Below the form: a ทัพเสริมในหมู่บ้านนี้ `.panel` listing
    `reinforcements_here` (from_village.name + units) with a เรียกกลับ button
    that recalls every `troop_id` in sequence then toasts and refreshes
    (ไม่มีทัพเสริม when empty); and a ทัพ `.panel` rendering `movements`
    (arrow + mission label + target + units + countdown, hostile rows
    `.negative`; ไม่มีทัพเคลื่อนที่ when empty).
  - Returns a cleanup function that clears the pending preview timer.

## CSS
Appended a `/* map + rally */` section: `.map-canvas` (responsive 600px,
touch-action none), `.map-wrap`, `.map-controls`, `.map-arrows`, `.map-coords`,
`.unit-rows`, `.unit-row`, and `.rally-form` input/select sizing. No existing
rules were modified.

## Limits / notes
- Map tiles are matched by exact (x, y) from the fetched 15x15 set; the server
  wraps coordinates so no client-side wrap is needed.
- The catapult target is only sent when catapult is selected and mission is
  attack; otherwise `catapult_target` is null.
- All DOM is built with `h()`/`clear()`; no `innerHTML` is used.
- Thai strings are copied verbatim from the task spec.
