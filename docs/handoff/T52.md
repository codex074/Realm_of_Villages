# T52 handoff: farm lists — service + API

## What was done
Implemented saved farm lists (raid target lists) on top of the existing
`farm_lists` / `farm_list_entries` tables (migration 0004): a service module
and a FastAPI router, wired into the app.

## Files
- `realm/services/farmlists.py` (new) — service logic.
- `realm/api/routes/farmlists.py` (new) — routes + pydantic body models
  (`CreateListBody`, `AddEntryBody`, `SendListBody`) defined locally.
- `realm/api/main.py` (small edit) — import + `include_router(farmlists.router, prefix="/api")`.
- `tests/services/test_farmlists.py` (new) — 16 service tests.
- `tests/api/test_api_farmlists.py` (new) — 4 API tests (CRUD, errors, send, 404 for another player's list).

## Public functions (realm/services/farmlists.py)
- `create_list(s, player_id, village_id, name, now) -> FarmList`
- `delete_list(s, player_id, list_id) -> None`
- `add_entry(s, player_id, list_id, x, y, units, now, cfg) -> FarmListEntry`
- `remove_entry(s, player_id, list_id, entry_id) -> None`
- `get_lists(s, player_id) -> list[dict]`
- `send_list(s, player_id, list_id, now, cfg, entry_ids=None) -> list[dict]`
- Constants: `MAX_LISTS = 10`, `MAX_ENTRIES = 100`.

## Routes (prefix /api)
- `GET /farmlists`
- `POST /farmlists` `{village_id, name}`
- `DELETE /farmlists/{id}`
- `POST /farmlists/{id}/entries` `{x, y, units}`
- `DELETE /farmlists/{id}/entries/{entry_id}`
- `POST /farmlists/{id}/send` `{entry_ids?: list[int]}` → `{"results": [...]}`

## Limits / rules
- Name stripped, 1..30 chars → `INVALID_TARGET` "ชื่อรายการไม่ถูกต้อง".
- Max 10 lists per player → `INVALID_TARGET` "รายการฟาร์มเต็มแล้ว".
- Max 100 entries per list; duplicate (x, y) in a list → `INVALID_TARGET` "มูีเป้าหมายนนี้ในรายการแล้ว".
- Units must be a non-empty dict of known `cfg.units` keys with positive ints → `INVALID_UNITS` "ระบุทหารไม่ถูกต้อง".
- Not the player's list/entry → `NOT_FOUND` "ไม่พบรายการฟาร์ม" / "ไม่พบเป้าหมาย".
- `send_list` sends `Mission.RAID` per entry via `military.send_troops`, each inside
  `s.begin_nested()` so one failure does not undo the others; per-entry result is
  `{"entry_id", "ok", "error", "movement_id"}`.
- Mutations use `require_running`; `datetime.now(UTC)` only in the routes.
