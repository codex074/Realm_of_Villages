# T06a handoff — API Phase 0 (app factory, deps, schemas, state/villages/admin routes)

## What was done
Implemented the FastAPI HTTP API for Phase 0 per BUILD.md section 9: app factory,
dependencies, request schemas, and the routes `GET /api/state`, `GET /api/meta`,
`GET /api/villages/{id}`, `PATCH /api/villages/{id}`, `GET /api/villages/{id}/slots/{slot}`,
`POST /api/villages/{id}/build`, `POST /api/admin/pause`, `POST /api/admin/resume`,
`POST /api/admin/new-world`. A `GameError` exception handler maps codes to HTTP
status (NOT_FOUND→404, FORBIDDEN→403, WORLD_ENDED→409, everything else→400) with the
`{"error": {"code", "message"}}` body. All routes are plain `def` (sync) functions so
FastAPI runs them in a threadpool with the sync session.

## Public functions
- `main.create_app(serve_static: bool = True) -> FastAPI` — builds the app, registers
  the `GameError` handler, includes the three routers under `/api`, and (when
  `serve_static` and `<repo>/web` exists) mounts `StaticFiles(html=True)` at `/` after
  the API routers. No websocket code yet (a later task adds `/ws`).
- `deps.get_session()` — generator yielding one `session_scope()` session per request.
- `deps.get_cfg()` — `load_config()` (lru_cached).
- `deps.get_world(s)` — newest `World` row of ANY status (`order_by(id.desc()).limit(1)`);
  none → `GameError(NOT_FOUND, "ไม่พบโลก")`.
- `deps.get_now(world)` — `worlds.world_now(world, datetime.now(UTC))`.
- `deps.get_player(s, world)` — the single non-bot `Player` of the world; none → NOT_FOUND.
- `deps.require_running(world)` — raises `GameError(WORLD_ENDED, "โลกนี้จบแล้ว")` when
  `world.status != "running"`; used on build, rename, pause, resume (NOT on new-world).
- `deps.random_seed()` — `random.randrange(1, 2**31)`.
- `schemas.BuildBody(slot, type)`, `schemas.RenameBody(name)`,
  `schemas.NewWorldBody(player_name, tribe, seed=None, speed=1, bot_count=30)`.
- `routes.state.build_state(s, world, cfg) -> StateView` — shared StateView builder
  (game_now, paused, speed, ends_at, world_id, player {id,name,tribe}, village briefs
  ordered by id, unread_reports count); imported by `admin.py`.
- `routes.state.state`, `routes.state.meta` — meta returns buildings/units/tribes
  (Thai names + stats), `speeds [1,3,5,10]`, and slot ranges from `realm.core.slots`.
- `routes.villages.get_village / rename_village / get_slot / build` — thin wrappers over
  `realm.services.villages` (`get_village_view`, `rename_village`, `get_slot_view`,
  `build`); build returns a `BuildQueueView` built from the `BuildQueue` row.
- `routes.admin.pause / resume / new_world` — call `worlds.pause/resume/create_world`
  with `datetime.now(UTC)` and return `build_state(...)`.

## Tests (tests/api/test_api_phase0.py)
`TestClient(create_app(serve_static=False))` with `app.dependency_overrides[get_session]`
yielding the rollback-protected `s` fixture (nothing is committed). Covers: new-world
→ 200 with world info; state (player name, 1 village, paused false, speed 1,
unread_reports 0); village view (40 buildings, resources ≈750 each via
`pytest.approx(750, abs=1)`); build → 200 BuildQueueView slot 1, repeat → 400
`QUEUE_FULL`; slots/1 shows the queued woodcutter; rename → 200 and visible in next
state; build on unknown village → 404 NOT_FOUND; pause/resume toggle `paused`;
meta (16 buildings, 9 units, 3 tribes with Thai fields); all mutating routes on a
`status='ended'` world → 409 WORLD_ENDED; state with no world rows → 404 NOT_FOUND
(all tables deleted in FK order).
