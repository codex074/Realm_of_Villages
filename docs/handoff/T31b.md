## Routes (prefix /api/alliance)
- `GET /` → `alliances.my_alliance` (object or null).
- `POST /` body `{name}` → `create_alliance`, returns `my_alliance`.
- `GET /invites` → `my_invites`.
- `POST /invite` body `{player_name}` → case-insensitive name lookup in the
  player's world (404 NOT_FOUND 'ไม่พบผู้เล่น' when absent; the service raises
  400 INVALID_TARGET for bots), then `invite()`, returns `{"ok": true}`.
- `POST /invites/{alliance_id}/accept` → `accept_invite`, returns `my_alliance`.
- `POST /invites/{alliance_id}/decline` → `decline_invite`, `{"ok": true}`.
- `POST /leave` → `leave`, `{"ok": true}`.
- `POST /kick` body `{player_id}` → `kick`, `{"ok": true}`.
- `GET /messages?after=0&limit=50` → `list_messages`.
- `POST /messages` body `{text}` → `post_message`, returned in `list_messages` shape.

All routes use `deps.get_player` + `deps.get_session`; mutating routes also use
`deps.require_running`. Current time is `datetime.now(timezone.utc)` inside the
routes (allowed at the API layer); the service commits via the session dependency.

## Public functions
`my_alliance`, `create_alliance`, `my_invites`, `invite`, `accept_invite`,
`decline_invite`, `leave`, `kick`, `list_messages`, `post_message` (route
handlers), plus private helper `_find_player_by_name`.

## Test notes
- Uses the same rollback-`s` fixture pattern as `test_api_phase0.py`
  (`TestClient(create_app(serve_static=False))` + `dependency_overrides[get_session]`).
- Extra human players are created as real `Player` rows and set up through the
  service functions; routes are exercised as the single default human.
- Note: the service's `accept_invite` deletes ALL of the player's invites, so the
  decline test runs before the accept test.

## Limits / TODO
- `POST /messages` returns the posting player's name from the requesting player
  object (always the poster, so equivalent to the service's lookup).
- No pagination cap beyond the service's `limit` parameter is enforced at the
  API layer (matches the service contract).
