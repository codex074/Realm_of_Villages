# T51 handoff: map protection flags + find_nearest population filter

## What was done
- `worlds.get_map` gained a last optional keyword `now: datetime | None = None`. Each village
  dict in the `MapView` now also carries `protected` (True when `now` is given and the owner's
  `protection_until > now`, else False) and `protected_until` (the owner's `protection_until`
  datetime when protected, else None).
- `worlds.find_nearest` gained keyword parameters `now: datetime | None = None`,
  `min_pop: int | None = None`, `max_pop: int | None = None` and `cfg: GameConfig | None = None`
  (all appended after `limit`, so old positional calls keep working). For `kind='village'` rows
  now carry `population` (computed with `realm.core.economy.population` over the village's
  Building (type, level) pairs; 0 when `cfg` is None) and `protected` (same rule as the map).
  When `min_pop`/`max_pop` are given, only villages with `min_pop <= population <= max_pop`
  are kept (non-village kinds ignore them). Ordering is unchanged.
- `GET /api/map` passes `now=Depends(deps.get_now)`.
- `GET /api/map/nearest` accepts optional query params `min_pop` and `max_pop` (ints) and passes
  `cfg=Depends(get_cfg)` and `now=Depends(get_now)`.

## Files

  limit=20, now=None, min_pop=None, max_pop=None, cfg=None) -> list[dict]`

## Limits / TODO
- `find_nearest` village population is computed only for the village kind (one extra query for
  buildings); non-village kinds never populate `population`/`protected`.
- `protected_until` is the raw owner `protection_until` datetime (serialized as ISO by FastAPI).
- No new Thai strings were introduced.
