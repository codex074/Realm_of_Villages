# T23a — Oasis: animals at world creation, respawn event, combat animal stats

## What was done
Added wild animals to oases: deterministic starting counts at world creation, a
recurring `OASIS_RESPAWN` event that regrows animals on unowned oases, and a
fixed-stats defense path in combat for animal groups.

## Files changed
- `realm/core/worldgen.py` — new `oasis_animals(seed, x, y, cfg) -> dict[str, int]`
  (pure, deterministic via `random.Random(f"{seed}:oasis:{x}:{y}")`).
- `realm/core/combat.py` — `ArmyGroup` gains a last field
  `stats: dict[str, tuple[float, float]] | None = None` (unit -> (def_inf, def_cav)).
  In the defense sum, a group with `stats is not None` uses `stats[unit]` directly
  (ignoring tribe multipliers and upgrades); other groups behave as before.
  Animals never attack (they are only ever used as defender groups).
- `realm/services/worlds.py` —
  1. `create_world` now sets `'animals'` on oasis tile rows (other kinds get `None`).
  2. After scheduling `ROUND_END`, schedules the first `OASIS_RESPAWN` at
     `game_epoch + respawn_hours*3600/speed` with payload `{}`.
  3. New `respawn_oases(s, world_id, now, cfg) -> None`: no-op for missing/ended
     worlds; for every unowned oasis tile computes the target counts and grows each
     animal by `min(target, current + ceil(target * respawn_fraction))`, assigning
     `tile.animals` only when it changed; schedules the next `OASIS_RESPAWN` at
     `now + respawn_hours*3600/world.speed`.
- `realm/engine/handlers.py` — new `handle_oasis_respawn(s, ev, cfg)` calling
  `worlds.respawn_oases`, registered in `HANDLERS` under `EventType.OASIS_RESPAWN`.

## Public functions added
- `realm.core.worldgen.oasis_animals(seed, x, y, cfg) -> dict[str, int]`
- `realm.services.worlds.respawn_oases(s, world_id, now, cfg) -> None`
- `realm.engine.handlers.handle_oasis_respawn(s, ev, cfg) -> None`

## Tests
- `tests/core/test_oasis.py` (pure): determinism, exact keys/bounds, range extremes
  over 200 coordinates, and hand-computed battles against animal-stats defenders
  (30 and 20 swordsmen) plus a normal (stats=None) group regression check.
- `tests/services/test_oasis_respawn.py` (DB): animals on oasis tiles at creation,
  first `OASIS_RESPAWN` timing at speed 1 (43200s) and speed 10 (4320s), respawn
  growth math, full-target no-op, owned-oasis skip, next-event scheduling, and
  running the handler through `engine.worker.process_next`.

## Existing tests adjusted (only for the new OASIS_RESPAWN event)
- `tests/services/test_worlds.py` — fresh-world event count `== 1` -> `== 2`.
- `tests/services/test_round.py` — `process_next` now picks the earlier
  OASIS_RESPAWN ticks first, so the ROUND_END assertion loops until that event runs.

## Verification
- `uv run pytest tests -q -rs` -> 383 passed.
- `uv run ruff check .` -> all checks passed; files formatted with `ruff format`.

## Limits / TODO
- Owned-oasis animal growth is skipped entirely here (ownership is handled by the
  remaining T23 parts); unowned oases respawn regardless of distance to a village.
- Animal combat stats are defense-only; there is no attack path for animals.
