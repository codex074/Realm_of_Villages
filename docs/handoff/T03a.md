# T03a handoff — db: SQLAlchemy models + session

## What was done
Implemented the full database schema from BUILD.md section 7 as SQLAlchemy 2.0 typed
ORM models, plus the engine/session module.

## Files
- `realm/db/models.py` — `Base` (DeclarativeBase) + 12 models:
  `World, Player, BotProfile, Tile, Village, Building, BuildQueue, Troop,
  TrainingQueue, Movement, Event, Report`.
- `realm/db/session.py` — `engine`, `SessionLocal`, `session_scope()`.

## Public API
- `Base` — declarative base; `Base.metadata.tables` holds all 12 tables
  (`worlds, players, bot_profiles, tiles, villages, buildings, build_queue,
  troops, training_queue, movements, events, reports`).
- `session_scope()` — context manager: commits on success, rolls back on
  exception, always closes the session.

## Key decisions / notes
- Timestamps: `DateTime(timezone=True)`; resources: `sqlalchemy.Double`;
  JSON: `JSONB` (postgresql dialect).
- BIGSERIAL ids: `BigInteger` PK with autoincrement.
- `server_default` used for: `'running'`, `'pending'`, `'moving'`, `0`, `1.0`,
  `100`, `false`, `'{}::jsonb'` so a hand-written alembic migration matches.
- FKs: `players.world_id -> worlds.id`, `villages.world_id/player_id`,
  `bot_profiles.player_id -> players.id` (PK), `troops.home_village_id /
  location_village_id -> villages.id`, `movements.world_id/player_id/
  from_village_id`, `events.world_id`, `reports.player_id`, `build_queue.
  village_id`, `training_queue.village_id`, `buildings.village_id`.
- Plain nullable `BigInteger` WITHOUT FK (per spec): `players.capital_village_id`,
  `tiles.oasis_owner_village_id`, `movements.to_village_id`, `build_queue.event_id`,
  `worlds.winner_player_id`.
- Composite PKs: `tiles(world_id,x,y)`, `buildings(village_id,slot)`.
- Uniques: `villages(world_id,x,y)`, `troops(home_village_id,location_village_id,unit)`.
- Named indexes (for the migration): `ix_events_world_id_status_due_at`,
  `ix_reports_player_id_created_at` (created_at via `desc()`),
  `ix_movements_to_village_id_status`, `ix_movements_from_village_id_status`,
  `ix_troops_location_village_id`, `ix_troops_home_village_id`,
  `ix_bot_profiles_next_think_at`.
- No relationships, no helper methods, no extra columns.
