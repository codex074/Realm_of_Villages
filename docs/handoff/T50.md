## Public functions / routes
1. `intel.incoming_attacks(s, player_id, now) -> list[dict]`
   - GET `/api/incoming`
   - Moving movements with mission attack/raid/scout targeting one of the
     player's villages, sent by another player; sorted by `arrive_at` asc.
   - Item keys: `id`, `mission`, `arrive_at`, `to_village_id`,
     `to_village_name`, `from` `{x, y, name}` (attacker's from_village).
     Units are NOT revealed.
2. `intel.travel_times(s, player_id, village_id, to_x, to_y, cfg) -> dict`
   - GET `/api/villages/{village_id}/travel?x=&y=`
   - NOT_FOUND (villages.VILLAGE_NOT_FOUND_TH) when the village does not exist,
     FORBIDDEN (villages.FORBIDDEN_TH) when it belongs to another player.
   - Coordinates are torus-wrapped like `military._check_send`.
   - Returns `{'distance': round(dist, 2), 'units': {unit: seconds}}`;
     seconds come from `movement.travel_time_s({unit: 1}, player.tribe, dist,
     world.speed, cfg)` for each unit type with a positive count of troops at
     home (home_village_id == location_village_id == village.id).
3. `intel.tile_intel(s, player_id, x, y) -> dict`
   - GET `/api/map/intel?x=&y=`
   - Scans the player's own Report rows, newest first, at most 300
     (`REPORT_SCAN_LIMIT`). Matches reports whose `data['target']` has
     `x`/`y` equal to the given coordinates.
   - `last_attack`: newest report with `data['mission']` in ('attack', 'raid')
     -> `{report_id, created_at, mission, loot, attacker_won}`.
   - `last_scout`: newest report with `data['mission'] == 'scout'` and
     `data['success'] is True` -> `{report_id, created_at, troops, resources}`.
   - Each is `None` when not found.
   - Attacker check: battle report payloads (`military._resolve_battle_arrival`)
     store `data['attacker']['player']` (a name, no `player_id`) and scout
     payloads (`military._resolve_scout_arrival`) have no `attacker` key at
     all; both kinds are created for the attacker's own `player_id`, so the
     `Report.player_id` column is authoritative. The `data['attacker']` key is
     only used as a defensive filter when it happens to contain a `player_id`
     (documented in a comment in intel.py).

## Limits / decisions
- `incoming_attacks` ignores the `now` parameter beyond the contract (all
  status='moving' rows are, by definition, not yet arrived).
- `tile_intel` scans at most the 300 newest of the player's reports.
- No new Thai strings were added; existing `villages` constants are reused.
