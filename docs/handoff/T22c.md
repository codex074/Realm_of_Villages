# T22c: api + web — smithy unit upgrades

## What was done
Wired the existing `realm.services.smithy` service to the HTTP API and exposed the
unit-upgrade options in the slot bottom sheet.

## Files
- `realm/api/routes/smithy.py` (new): `router = APIRouter()` with two `def` routes.
- `realm/api/schemas.py`: added `UpgradeBody(BaseModel): unit: str`.
- `realm/api/main.py`: imported and included `smithy.router` with prefix `/api`.
- `web/js/views/slotpanel.js`: added `appendSmithy`/`doUpgrade` and a smithy section
  in `openSlotPanel` (only when the slot's building type is `smithy`).
- `tests/api/test_api_smithy.py` (new): 7 tests.

## Public functions / endpoints
- `GET /api/villages/{village_id}/upgrades` -> `list[UpgradeOption]`
  (`smithy.get_upgrade_options(s, player.id, village_id, now, cfg)`).
- `POST /api/villages/{village_id}/upgrade` body `{unit}` -> `UpgradeOption`
  (`smithy.start_upgrade(...)`, then the matching option re-read via
  `get_upgrade_options`). Guarded by `require_running` (409 WORLD_ENDED when not running).
- Both use `get_session`, `get_cfg`, `get_player`, `get_now` deps, matching `routes/military.py`.

## Web behaviour
When the current slot building is `smithy`, fetch `/villages/{id}/upgrades` and append an
"อัปเกรดหน่วย" section: one block per option with `<name_th> เลเวล <level>`; costs (`.negative`
when lacking), time via `fmtDuration`, missing lines, and a primary "อัปเกรด" button
(disabled when not affordable). Click POSTs the upgrade, toasts "เริ่มอัปเกรดแล้ว" and refreshes;
on `ApiError` toasts the message and re-enables. `finishes_at` shows a countdown span;
`target_level == null` shows "เลเวลสูงสุดแล้ว"; empty list shows "ไม่มีหน่วยที่อัปเกรดได้".
A failing fetch is swallowed so it never breaks the rest of the panel.

## Tests
7 tests: GET lists 6 upgradable units with the level-1 spearman cost
`{wood:700, stone:500, iron:300, food:500}` and `time_s` 1800.0; POST sets `finishes_at`
and `affordable=False`; second POST -> 400 QUEUE_FULL; unit `scout` -> 400 INVALID_UNITS;
unknown village -> 404; no smithy -> 400 REQUIREMENTS_NOT_MET; world ended -> 409 while GET 200.
