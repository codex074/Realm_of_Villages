# T22b: unit upgrades — core formulas, smithy service, combat integration

## What was done
Implemented smithy unit upgrades (T22):

- **Core formulas** (`realm/core/units.py`):
  - `upgrade_multiplier(level, cfg)` = 1 + bonus_per_level * level
  - `can_upgrade(unit, cfg)` — unit type in `cfg.upgrades.unit_types`
  - `upgrade_cost(unit, tribe, target_level, cfg)` — unit cost x cost_unit_multiple x cost_growth^(L-1), each resource floored with `math.floor(x + 1e-9)`
  - `upgrade_time_s(target_level, speed, cfg)` — time_base_s x time_growth^(L-1) / speed, minimum 1.0
  - `unit_defense(unit, tribe, cfg, upgrade_level=0)` — both values multiplied by the upgrade multiplier (applied after the base rounding so combat powers stay exact; default 0 keeps old results)
- **Combat** (`realm/core/combat.py`): `ArmyGroup` gained `upgrades: dict[str, int]` (default empty). Attacker attack sums multiply each unit's attack by its upgrade multiplier; defender sums pass the group's upgrade level to `unit_defense`.
- **Service** (new `realm/services/smithy.py`):
  - `effective_levels(s, village_id, now)` — level + 1 when the in-progress upgrade is finished and upgrading_to == level + 1; only units with level > 0
  - `finalize(s, village_id, now)` — persists finished upgrades
  - `start_upgrade(s, player_id, village_id, unit, now, cfg)` — lock, owner check, settle, finalize, unit check (INVALID_UNITS), smithy level check (REQUIREMENTS_NOT_MET), queue check (QUEUE_FULL), cap min(max_level, smithy level) (MAX_LEVEL), cost check (INSUFFICIENT_RESOURCES), deduct, upsert row, after_change, notify
  - `get_upgrade_options(s, player_id, village_id, now, cfg)` — one `UpgradeOption` per upgradable unit in YAML order
- **Views** (`realm/services/views.py`): new `UpgradeOption` model.
- **Military** (`realm/services/military.py`, small edits only): attacker group in `_resolve_battle_arrival` and each defender group in `_defender_groups` (new `now` parameter) carry `upgrades=smithy.effective_levels(...)`.

## Limits / decisions
- `finalize` is lazy: finished upgrades are persisted on the next smithy/military touch, never on a timer.
- One upgrade at a time per village (QUEUE_FULL while any row is upgrading).
- `get_upgrade_options.affordable` is False for every option while any upgrade is running (single queue).
- `unit_defense` applies the multiplier after the base `round(..., 2)` so combat powers match the spec values exactly (e.g. 66.125 at level 10).
- `upgrade_cost` floors with a +1e-9 epsilon to avoid float noise.
