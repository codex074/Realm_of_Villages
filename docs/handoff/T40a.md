# T40a — Phase 4: alliance rules (no attacks on allies) + alliance name in ranking and map

## What was done
Alliances now matter in the game rules: hostile missions (ATTACK, RAID, SCOUT) cannot target a
village owned by an ally, and the alliance name is surfaced in the world ranking and the map.

## Files changed
- `realm/services/alliances.py` — appended `alliance_names(s, world_id)`.
- `realm/services/views.py` — added `alliance: str | None = None` to `RankingRow` (after `monument`).
- `realm/services/ranking.py` — `get_ranking` calls `alliance_names` once and fills `RankingRow.alliance`.
- `realm/services/worlds.py` — `get_map` adds `alliance` and `is_ally` to each village dict.
- `realm/services/military.py` — `_check_send` blocks hostile missions at an ally village
  (new constant `ALLY_TARGET_TH = "โจมตีพันธมิตรไม่ได้"`); imported the `alliances` service.
- `tests/services/test_alliance_rules.py` — new test file.

## Public functions
- `alliances.alliance_names(s: Session, world_id: int) -> dict[int, str]` — maps player_id to
  alliance name for every member of every alliance in the world (single join of
  `AllianceMember` and `Alliance` filtered by world).

## Behaviour
- `get_ranking`: rows carry `alliance` (name for members, `None` otherwise); ordering unchanged.
- `get_map`: each village dict gains `alliance` (owner's name or `None`) and `is_ally`
  (`True` only when the owner shares the viewer's alliance and is not the viewer).
- `military.send_troops`: ATTACK/RAID/SCOUT at an ally village raise `GameError(INVALID_TARGET,
  "โจมตีพันธมิตรไม่ได้")`. REINFORCE and TRADE are unaffected. After the leader kicks the
  member, the attack is allowed again.

## Limits / notes
- `alliance_names` is computed once per `get_ranking` / `get_map` call.
- The ally check in `_check_send` runs after the self-target check and before the protection
  check, so the ally message takes precedence over PROTECTED.
- No circular import: `alliances.py` does not import `military`.
