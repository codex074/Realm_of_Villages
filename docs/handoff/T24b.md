# T24b — Bot: conquer and defend modules

## What was done
Added the `conquer` and `defend` bot modules (T24 part b) and wired them into the
brain. Bots act only through `realm.services`.

## Files

- `tests/bot/test_conquer_defend.py` — 20 hand-computed tests.

## Public functions
- `modules.conquer(ctx) -> list[Action]`:
  - A) CHIEFS AT HOME: if `troops_home['chief'] >= 1`, find non-capital,
    unprotected, in-`raid_radius`, `recent_fails < 2` enemy villages (one
    villages+players query, one grouped buildings query for populations). Army =
    all home units that are not scout/settler (includes chiefs). Target qualifies
    when `attack >= 400 + 25 * population`. Best = lowest loyalty, ties by
    distance then id. Returns one `attack` action (score 3.5).
  - B) TRAIN CHIEFS: when no attack, palace meets chief requirements, player has
    no chief anywhere (home Troop rows + moving Movement rows), and no chief
    TrainingQueue row: `count = min(2, int(min stock/cost))` over cost>0 resources.
    Returns one `train` action (score 3.0).
- `modules.defend(ctx) -> list[Action]` (only when
  `cfg.bot_difficulties[profile.difficulty].defend`): on an incoming
  attack/raid Movement (other player, `arrive_at - now <= 900 / world.speed` s):
  1) EVACUATE — send home carry>0 units to the nearest unprotected enemy village
  (not the attacker's, within 30 tiles) as a `raid` (score 6.0); 2) SPEND — train
  the best trainable unit (unit_mix filtered by trainable, spearman fallback)
  with `count = int(min stock/cost)` as a `train` (score 5.5).

## Limits / notes
- The conquer threshold `400 + 25 * population` is a fixed formula from the task
  spec; there is no matching `cfg` key, so it is written literally (contract as
  given).
- `defend` uses the fixed 30-tile evacuation radius and 900 s (15 min) arrival
  window, scaled by `world.speed`, as specified.
- `conquer`/`defend` are read-only on the DB; all mutations happen in
  `Action.execute` via services.
