# T16b — bot: brain.think, worker loop, `realm bots`, compose service

## What was done
Implemented the bot decision brain, the bot worker loop, the `realm bots` CLI
command, and enabled the `bots` service in docker-compose. Bots act only through
`realm.services` (via `Action.execute`); they never write villages/troops directly.

## Files
- `realm/bot/brain.py` (new)
- `realm/bot/worker.py` (new)
- `realm/cli.py` (edited: `bots` command now runs the worker)

## Public functions
- `brain.collect_candidates(s, bot, profile, now, cfg, rng) -> list[tuple[Action, Village]]`
  - For each bot village (ordered by id): `villages.lock_village` + `settle_village`,
    build a module context, gather actions from the five modules, multiply each
    action's score by its module's personality weight
    (field_upgrades→economy, storage→storage, build_order→build, training→military,
    raid→raid). While elapsed game days (`(now - world.game_epoch)/86400`) are below
    `personality.active_from_day / world.speed`, the military and raid weights are
    additionally multiplied by 0.3. Zero-weight (or damped-to-zero) modules are
    dropped; only score > 0 actions are kept. New `Action` objects are created via
    `dataclasses.replace` (shared module actions are never mutated).
- `brain.think(s, bot, profile, now, cfg, rng) -> list[Action]`
  - 1) `memory.update_from_reports`; 2) sort candidates by score descending (stable);
    3) walk them: skip with probability `difficulty.skip_chance` (skips don't count),
    execute the rest inside `with s.begin_nested():`, catching `GameError` (savepoint
    rolls back, action doesn't count); stop after `difficulty.max_actions` successes;
    4) return the successfully executed actions (weighted scores).
- `worker.think_due_bots(s, world, now, cfg, rng, limit=10) -> int`
  - `SELECT BotProfile, Player JOIN Player ... WHERE Player.world_id == world.id AND
    BotProfile.next_think_at <= now ORDER BY next_think_at LIMIT limit
    FOR UPDATE SKIP LOCKED (of=BotProfile)`. For each: `brain.think` inside a
    savepoint; any exception is logged (`logging.getLogger('realm.bot').exception`)
    and only that savepoint is rolled back. In all cases
    `profile.next_think_at = now + think_interval_min*60/speed` seconds. Returns the
    number of bots processed (attempts, failures included).
- `worker.run_forever(cfg) -> None`
  - `logging.basicConfig(level=settings.log_level)`; SIGTERM/SIGINT set a stop flag
    (graceful, like `realm/engine/worker.py`). Loop: one `session_scope()`, load the
    newest running unpaused world (sleep 1 s if none), `now = worlds.world_now(world,
    datetime.now(UTC))`, `think_due_bots(..., random.Random(), limit=10)`; sleep 1 s
    when nothing was processed; unexpected exceptions are logged + 1 s sleep.

## CLI / compose
- `realm bots` lazily imports `run_forever` and `load_config` and calls
  `run_forever(load_config())`. Other commands unchanged.
- docker-compose `bots` service: `command: ["realm","bots"]`, same anchor/env_file/
  depends_on/restart as `engine`.

## Tests
- brain: hard farmer executes ≥1 (≤6) actions incl. a build, exactly one build_queue
  row (town_hall<10 → single queue, other builds fail with swallowed GameError) and
  stock decreases by exactly the executed build costs; easy bot ≤1 action; farmer
  (raid weight 0) never creates a raid movement; raider sends a raid movement with the
  right units and troops leave home; warlord military weight is ×0.3 before
  active_from_day and full after (compared against the raw module score at the same
  now); memory records the latest battle report id; static guard that bot sources
  never contain direct village/troop mutation substrings.
- worker: only due bots of the given world are processed (limit 1 → one advanced,
  second call advances the other, third finds none); next_think_at == now +
  think_interval_min*60/speed (300 s at speed 1, 30 s at speed 10); bots of other
  worlds untouched; a raising `brain.think` is logged, rolled back (village wood stays
  750) and the bot is still rescheduled; compose has a `bots` service with command
  `['realm','bots']`; `realm --help` lists `bots`.

## Notes / limits / TODO
- `tests/bot/__init__.py` was added because `tests/bot/test_worker.py` and the
  pre-existing `tests/engine/test_worker.py` share a basename; without a package the
  default pytest `prepend` import mode collides ("import file mismatch"). Making
  `tests/bot` a package resolves it while keeping the mandated filename.
- No new dependencies were added.
