# T05 handoff — engine worker + BUILD_COMPLETE

## What was done
Implemented the event engine per BUILD.md T05: a worker that picks the earliest due
pending event of the newest running (unpaused) world and runs its handler inside a
savepoint, plus the BUILD_COMPLETE handler and stubs for the remaining event types.

## Files
- `realm/engine/handlers.py` (new)
- `realm/engine/worker.py` (new)
- `realm/cli.py` (edited: `engine` command now runs the worker; lazy imports)
- `tests/engine/test_worker.py` (new)

## Public functions
- `handlers.Handler` — type alias `Callable[[Session, Event, GameConfig], None]`.
- `handlers.handle_build_complete(s, ev, cfg)` — calls
  `villages.complete_build(s, ev.payload["build_queue_id"], ev.due_at, cfg)`;
  always uses `ev.due_at` as `now`, never the real clock.
- `handlers.handle_train_tick` / `handle_movement_arrive` / `handle_round_end` —
  raise `NotImplementedError('<task> not implemented yet')` (T11, T13, T14).
- `handlers.handle_starvation_check` — no-op, logs at DEBUG only.
- `handlers.HANDLERS: dict[EventType, Handler]` — all 5 event types.
- `worker.process_next(s, world, now, cfg) -> bool` — selects the pending event of
  this world with `due_at <= now`, ordered by `(due_at, id)`, `LIMIT 1 FOR UPDATE
  SKIP LOCKED`; none → `False`. Runs `HANDLERS[EventType(ev.type)]` inside
  `s.begin_nested()` (savepoint); success → `status='done'`; any exception →
  savepoint rolls back the handler's changes, `status='failed'`, `attempts += 1`,
  `last_error = repr(exc)[:2000]`, `logger.exception`, still returns `True`.
  Flushes and logs INFO (type, id, status, elapsed ms) for every processed event.
- `worker.run_forever(cfg, idle_sleep=0.5) -> None` — `logging.basicConfig(level=
  settings.log_level)`; SIGTERM/SIGINT set a stop flag (graceful: finishes the
  current event). Each iteration opens one `session_scope()` transaction, loads the
  newest world with `status='running'` and `paused_at IS NULL` (sleeps when none),
  computes `now = worlds.world_now(world, datetime.now(UTC))`, calls `process_next`
  once; sleeps `idle_sleep` when there was no work; unexpected exceptions are
  logged and followed by `sleep(1.0)`, loop continues.

## Tests (tests/engine/test_worker.py)
Build lifecycle (not due → False / due → True, level 1, queue row gone, event done,
idempotent), handler uses `ev.due_at` (`res_updated_at == t0+240s`, not `t0+1000s`),
due-time ordering with tie-break by id, failing handler (savepoint rollback of
`world.speed`, `failed`/`attempts=1`/`last_error`, session still usable, next event
processed), other-world and not-yet-due events not processed, MOVEMENT_ARRIVE →
`failed` with "not implemented", STARVATION_CHECK → `done`.

## Limits / notes
- Handlers are looked up in `HANDLERS` at call time, so tests can
  `monkeypatch.setitem(HANDLERS, ...)` (used by the tests).
- `process_next` handles exactly one event per call; the loop in `run_forever`
  drives repeated calls, one transaction per event.
- `run_forever` is not unit-tested (long-running loop); only `process_next` and the
  handlers are covered.
