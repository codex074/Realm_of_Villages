# T31a — Phase 3: Alliances service

## What was done
Implemented the alliances service (create / invite / join / leave / kick / chat) as a new
module `realm/services/alliances.py`. No existing file was edited. Services take the
session `s`, only `flush()` (never commit), never call `datetime.now()` (callers pass
`now`), and raise `GameError(code, thai_message)` with codes from `realm.services.errors`.

## Files
- `realm/services/alliances.py` (new)
- `tests/services/test_alliances.py` (new, 32 tests)

## Public functions
- `create_alliance(s, player_id, name, now) -> Alliance`
- `invite(s, actor_id, target_player_id, now) -> None`
- `accept_invite(s, player_id, alliance_id, now) -> None`
- `decline_invite(s, player_id, alliance_id) -> None`
- `leave(s, player_id, now) -> None`
- `kick(s, actor_id, target_player_id) -> None`
- `my_alliance(s, player_id) -> dict | None`
- `my_invites(s, player_id) -> list[dict]`
- `are_allies(s, a_id, b_id) -> bool`
- `post_message(s, player_id, text, now) -> AllianceMessage`
- `list_messages(s, player_id, after_id=0, limit=50) -> list[dict]`

Module constant: `MAX_MEMBERS = 20`.

## Limits / rules implemented
- Create: human only, not already in an alliance, name stripped 3..20 chars, name unique
  per world case-insensitive.
- Invite: leader only; target human, same world, not in an alliance, no duplicate invite;
  members + pending invites < MAX_MEMBERS.
- Accept: invite must exist, player not in an alliance, alliance below MAX_MEMBERS;
  adds member and deletes all of the player's invites.
- Leave: leader transfer to smallest (joined_at, player_id); empty alliance deletes its
  invites and messages.
- Kick: leader only, target must be a member of the same alliance, cannot kick self.
- Chat: member only, text stripped 1..300 chars; list returns newest `limit` of messages
  with id > after_id, oldest first.
