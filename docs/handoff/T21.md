# T21 — Loyalty, chiefs and conquering villages

## What was done

Implemented loyalty damage from surviving chiefs, village conquest, and palace-based
loyalty regeneration (BUILD.md T21).

- New `realm/services/conquest.py` with `apply_loyalty` and `conquer_village`.
- `realm/services/military.py` (small targeted edits only): `_resolve_battle_arrival`
  now calls `conquest.apply_loyalty` when `result.loyalty_damage > 0` (after loot is
  computed, before the return movement is created). When the village is conquered,
  all surviving chiefs are removed from the return units. The battle report's
  `data['loyalty']` is now the info dict (or `None` when there was no damage).
- `realm/services/villages.py` (small targeted edit only): `settle_village` regenerates
  loyalty when it is below 100: `min(100, loyalty + palace_level *
  cfg.combat.loyalty_regen_per_palace_level * world.speed * elapsed_hours)`, with the
  palace level queried only in that case. No palace -> no regeneration.
- `tests/services/test_conquest.py`: 6 tests covering loyalty reduction without
  conquest, full conquest (ownership, loyalty reset, chief removal from the return
  movement, battle + info reports, deletion of the old owner's troops/training/
  outgoing movement and their pending events, culture settled at arrival time for
  both players), capital protection, a failed attack (no damage, loyalty None),
  regeneration with cap, and a speed-10 world.

## Public functions

- `conquest.apply_loyalty(s, *, target, attacker_player, damage, now, cfg) -> dict`
  with keys `before`, `after`, `conquered`. No-op for `damage <= 0` or capitals.
- `conquest.conquer_village(s, target, new_owner, now, cfg) -> None`: settles culture
  for both players first, deletes all `Troop` rows with `home_village_id == target.id`
  (wherever located), deletes moving `Movement` rows from the village and cancels
  their `MOVEMENT_ARRIVE` events, deletes `TrainingQueue` rows and cancels their
  `TRAIN_TICK` events, transfers ownership, sets `is_capital = False`,
  `loyalty = cfg.combat.conquest_loyalty`, calls `villages.after_change`, notifies
  both players (kind `'village'`), and creates `'info'` reports for both owners with
  data `{'village': {'id', 'name', 'x', 'y'}}`.

## Limits / notes

- Conquered villages keep their buildings, stock and layout; only troops, outgoing
  movements and training are cleared, per the task spec.
- `apply_loyalty` is called only from the battle arrival path; raids never damage
  loyalty (combat only produces `loyalty_damage` for winning ATTACK missions).
- Loyalty regeneration happens inside `settle_village`, so it accrues on every
  settlement of a village with loyalty < 100 (views, battles, starvation, etc.).
- The return movement's own `MOVEMENT_ARRIVE` event is scheduled after the conquest
  cleanup, so it is not cancelled.
