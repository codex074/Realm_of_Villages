# T60 — Admin member management

## What was done
Added admin member management: list members, reset password, grant/revoke admin,
disable/enable accounts, and per-account audit trail.

- `realm/api/routes/members.py` (new) — FastAPI routes under `/api/admin/members`.

- `tests/services/test_members.py` (new)

## Public functions (services)
- `list_members(s, cfg) -> list[dict]` — accounts ordered by id with
  `id, username, is_admin, is_disabled, created_at, last_seen` (max `AuditLog.created_at`
  for the account, or None), `player` (None or `id/name/tribe/villages/population` from the
  newest world's `Building` rows via `realm.core.economy.population`) and `alliance`
  (name via `alliances.alliance_names`, or None). Buildings are loaded in one query for all
  of the world's villages.
- `set_password(s, actor_id, target_id, new_password) -> None` — validates length against
  `accounts.MIN_PASSWORD_LEN`, stores `accounts.hash_password`, deletes all target
  `AuthSession` rows unless `target_id == actor_id`.
- `set_admin(s, actor_id, target_id, value) -> None` — self edit is FORBIDDEN; demoting the
  last remaining admin is INVALID_TARGET.
- `set_disabled(s, actor_id, target_id, value) -> None` — self edit FORBIDDEN; disabling an
  admin is INVALID_TARGET; disabling also deletes the target's sessions.
- `audit_trail(s, target_id, limit=50) -> list[dict]` — newest first, limit clamped to 1..200.

## Routes
- `GET /api/admin/members`
- `POST /api/admin/members/{id}/password` `{password}`
- `POST /api/admin/members/{id}/admin` `{value}`
- `POST /api/admin/members/{id}/disabled` `{value}`
- `GET /api/admin/members/{id}/audit?limit=50`

All require auth mode (`settings.auth_required`) and an admin (via
`routes.admin._require_admin`); mutations return `{"ok": True}`.

## Limits / notes
- Services take the session, never commit, never call `datetime.now()`.
- `last_seen` is computed independently of world existence (works with no world).
- Player/alliance/village/building data only applies to the newest world.
