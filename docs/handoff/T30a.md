# T30a Handoff — Phase 3: accounts, sessions, auth API, get_player in auth mode

## What was done
Implemented login accounts, session management, the auth API, and auth-mode
player resolution. `settings.auth_required` (default False) toggles the mode:
- False (default): existing single-human behaviour, no cookie needed (phase 0/1 tests unchanged).
- True: every `get_player`-dependent route requires a valid `rov_session` cookie;
  the player is the `Player` with `account_id == account.id` in the world.

## Files
- `realm/services/accounts.py` (new): password hashing + account/session services.
- `realm/api/routes/auth.py` (new): register / login / logout / me.
- `realm/services/errors.py` (edited): added `UNAUTHENTICATED`, `NO_PLAYER`,
  `RATE_LIMITED`, `PAUSE_DISABLED`.
- `realm/api/main.py` (edited): status map `UNAUTHENTICATED->401`, `NO_PLAYER->404`,
  `RATE_LIMITED->429`; included the auth router with prefix `/api`.
- `realm/api/deps.py` (edited): added `get_account`; `get_player` now branches on
  `settings.auth_required` (read at call time).
- `realm/api/schemas.py` (edited): added `AuthBody`.
- `realm/api/routes/state.py` (edited, see Deviation below): `build_state` accepts an
  optional `player`; the `state` route now depends on `get_player`.
- `tests/services/test_accounts.py`, `tests/api/test_api_auth.py` (new).

## Public functions
`realm.services.accounts`:
- `COOKIE = "rov_session"`
- `hash_password(password) -> str` — scrypt (n=2**14, r=8, p=1, dklen=32), random 16-byte salt, `scrypt$<salt>$<hash>`.
- `verify_password(password, stored) -> bool` — constant-time via `hmac.compare_digest`; malformed stored value -> False.
- `register(s, username, password, now) -> Account` — validates username/password, case-insensitive duplicate check; first account is admin.
- `login(s, username, password, now, ttl_hours) -> tuple[str, Account]` — returns raw token, stores only sha256 hexdigest.
- `logout(s, token) -> None` — deletes session (unknown token no-op).
- `account_for_token(s, token, now) -> Account | None` — None for unknown/expired; deletes expired rows.
- `player_for_account(s, account) -> Player | None` — account's player in the newest world.

`realm.api.deps`:
- `get_account(request, s) -> Account | None`.
- `get_player(request, s, world) -> Player` — auth-mode aware.

`realm.api.routes.auth`: `register`, `login`, `logout`, `me` (all under `/api`).

## Deviation from WRITE list
`realm/api/routes/state.py` was edited (not in the WRITE list). The acceptance
criteria require `GET /api/state` to return 401 UNAUTHENTICATED / 404 NO_PLAYER /
200 depending on auth mode, but the original `state` route built its view directly
from the world's human player, bypassing `get_player`. Routing it through `get_player`
was the only way to satisfy those criteria. The change is minimal and backward
compatible: `build_state(s, world, cfg)` (used by admin pause/resume/new-world)
still defaults `player=None` and resolves the human player exactly as before.

## Limits / TODO
- `settings.rate_limit_per_10s` and `PAUSE_DISABLED` are defined but not yet wired
  into middleware/routes (later phase).
- No rate limiting or brute-force lockout on login yet.
- `me`/auth routes use `datetime.now(UTC)` in the API layer (allowed); services take `now`.
- No per-account "join world" flow yet; a player is bound to an account by setting
  `Player.account_id` (done directly in tests).
