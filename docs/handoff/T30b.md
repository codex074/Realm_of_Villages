# T30b handoff — Phase 3 part 2: join a running world, admin-only control, pause rule

## What was done
- `realm/services/worlds.py`
  - `join_world(s, account_id, name, tribe, real_now, cfg) -> Player`: joins the current
    running world. Validates (account not already in world, tribe known, name 2..20 chars
    stripped, name unique case-insensitively) with the exact Thai strings from the spec.
    Spawns on a valley tile (oasis_owner NULL) at torus distance in `[ring, ring+8]` from
    (0,0) where `ring` = max village distance from (0,0) clamped to `size//2 - 3`, at least
    `cfg.world.min_village_distance` from every village. Candidates sorted by (x,y), shuffled
    with `random.Random(f'{world.seed}:join:{account_id}')`, first taken; upper bound widened
    by 8 until `> size//2` then `INVALID_TARGET`. Creates the Player (is_bot False,
    account_id, protection_until = now + protection_hours*3600/speed) and a capital village
    named `บ้านของ{name}` with start resources, tile layout and 21 initial buildings.
  - `human_count(s, world_id) -> int`: count of non-bot players.
  - `pause()` now raises `PAUSE_DISABLED` when `human_count > 1`; `resume()` unchanged.
- `realm/api/routes/world_join.py` (new): `POST /api/world/join` (body `JoinBody{name, tribe}`).
  Only in auth mode (`settings.auth_required`), else `INVALID_TARGET`; requires an account
  (else `UNAUTHENTICATED`); requires a running world; returns `{'player': {id,name,tribe},
  'village': {id,name,x,y}}`.
- `realm/api/schemas.py`: added `JoinBody`.
- `realm/api/routes/admin.py`: in auth mode the three admin routes require an admin account
  (no account -> `UNAUTHENTICATED`, non-admin -> `FORBIDDEN`); `new-world` links the created
  human player to the admin account. With `auth_required` False behaviour is unchanged.
- `realm/api/main.py`: included the new `world_join` router under `/api`.
- `realm/api/routes/state.py`: NOT edited (already accepts `player` from T30a).
