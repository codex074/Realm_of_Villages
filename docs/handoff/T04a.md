## Public functions / classes
- `errors.GameError(code, message)` — stores `.code` and `.message`, passes message to `Exception`.
  Module constants: `NOT_FOUND`, `FORBIDDEN`, `INSUFFICIENT_RESOURCES`, `QUEUE_FULL`,
  `REQUIREMENTS_NOT_MET`, `MAX_LEVEL`, `INVALID_SLOT`, `INVALID_TARGET`, `INVALID_UNITS`,
  `NO_UNITS`, `PROTECTED`, `NOT_ENOUGH_CULTURE`, `WORLD_ENDED`.
- `events.schedule(s, world_id, etype, due_at, payload) -> Event` — inserts a pending `Event`
  (type stored as `etype.value`, `created_at=func.now()`), flushes, returns it.
- `events.cancel_pending(s, world_id, etype, match) -> int` — deletes PENDING events of that
  world/type whose JSONB payload `contains(match)`; returns rowcount.
- `notify.build_payload(world_id, player_ids, kind, village_id=None) -> str` — JSON string with
  keys `world_id`, `player_ids`, `kind`, `village_id`.
- `notify.notify(s, world_id, player_ids, kind, village_id=None) -> None` — executes
  `select(func.pg_notify('game_events', payload_json))`.
- `views.*` — all pydantic models from 8.9: `Coord`, `VillageBrief`, `BuildingView`,
  `BuildQueueView`, `TrainingView`, `MovementView`, `VillageView`, `CostView`, `SlotView`,
  `TrainOption`, `SendPreview`, `MapTile`, `MapView`, `ReportSummary`, `ReportDetail`,
  `RankingRow`, `StateView`. `Units` imported from `realm.core.types`.

## Limits / notes
- Service functions do not commit (per 8.1); callers control the transaction.
- `schedule`/`cancel_pending` take no `now` param; `created_at` uses the SQL `func.now()`.
- `cancel_pending` matches on `status == "pending"` and JSONB containment; done/failed and
  other type/world rows are untouched (verified by test).
