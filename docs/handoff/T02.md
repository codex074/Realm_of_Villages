# T02 handoff — core: clock, economy, construction, slots

## What was done
Implemented the pure (no DB/Session) core modules required by BUILD.md sections 4, 6.2, 6.3, 6.4,
with the exact function names/signatures from the contract, plus a real test suite for each.

## Files
- `realm/core/clock.py` — `game_now`, `scaled`
- `realm/core/economy.py` — `field_production`, `storage_capacity`, `hideout_capacity`, `population`,
  `gross_production`, `village_rates`, `village_capacity`, `settle`, `seconds_until_food_empty`,
  `culture_per_day`
- `realm/core/construction.py` — `building_cost`, `build_time_s`, `max_level`,
  `missing_requirements`, `queue_limit`
- `realm/core/slots.py` — `FIELD_SLOTS`, `CENTER_SLOTS`, `ALL_SLOTS`,
  `field_types_for_layout`, `slot_accepts`, `initial_buildings`
- `tests/core/test_clock.py`, `test_economy.py`, `test_construction.py`, `test_slots.py`

## Notes / decisions
- All numbers in tests are hand-computed from `realm/config/*.yaml` (not derived from the code).
- `building_cost` uses `math.floor` per resource (not round).
- `missing_requirements` returns Thai strings `ต้องมี {name_th} เลเวล {n}`, iterating `requires` in
  dict order; a requirement is missing when `levels.get(key, 0) < required`.
- `population` accepts a `Mapping[str,int]` or an iterable of `(btype, level)` pairs.
- `hideout_capacity` uses `cfg.tribes[tribe].modifiers.hideout_mult`; L=0 → 0.
- `max_level` returns `capital_max_level` only when `is_capital` and it is set, else `max_level`.
- `queue_limit` is 2 when `town_hall_level >= cfg.construction.second_queue_town_hall_level`, else 1.
- `field_types_for_layout` raises `ValueError` on layouts that do not have 4 parts summing to 18.
- `initial_buildings` yields 21 slots: 18 level-0 fields + town_hall(1) + rally_point(0) +
  wall(0); center slots stay empty.

## Limits / TODO
- `gross_production` only sums `kind == "field"` buildings (via their `produces`); non-field
  entries are ignored.
- `settle` clamps to `[0, capacity]` per resource and is a no-op when `now < updated_at`.
- No DB/Session usage; all time-dependent functions take `now: datetime` (tz-aware UTC).
