# T12a — core: units.py + movement.py

## What was done
Implemented the pure unit and movement math per BUILD.md sections 6.5 and 6.6, plus
hand-computed tests. All values are read from `GameConfig` (no hard-coded game numbers).

## Files
- `realm/core/units.py` — new
- `realm/core/movement.py` — new
- `tests/core/test_units.py` — new
- `tests/core/test_movement.py` — new

## Public functions
### units.py (BUILD.md 6.5)
- `unit_cost(unit, tribe, cfg) -> Res` — cost * unit_cost_mult, floored per resource.
- `train_time_s(unit, building_level, speed, cfg) -> float` — base * training_building_factor**(max(1,L)-1) / speed, min 1.0.
- `unit_speed(unit, tribe, cfg) -> float` — speed; cav units get cav_speed_mult.
- `army_speed(units, tribe, cfg) -> float` — min speed over count>0; ValueError if none.
- `carry_capacity(units, tribe, cfg) -> float` — sum(carry*count) * carry_mult.
- `troop_upkeep(units, cfg) -> float` — sum(upkeep*count).
- `unit_defense(unit, tribe, cfg) -> (def_inf, def_cav)` — inf_defense_mult applied only to type 'inf'.
- `missing_unit_requirements(unit, levels, cfg) -> list[str]` — Thai messages, same wording as construction.
- `validate_mission_units(mission, units, cfg) -> list[str]` — Thai errors per 5.3; ValueError on unknown unit.
- `army_value(units, cfg) -> float` — sum(cost.total() * count).

### movement.py (BUILD.md 6.6)
- `wrap(v, size) -> int` — maps to -(size//2)..size//2.
- `distance(x1, y1, x2, y2, size) -> float` — torus Euclidean.
- `travel_time_s(units, tribe, dist, speed, cfg) -> float` — dist/army_speed*3600/speed, min 1.0.

## Notes / limits
- Float-returning functions are rounded to 2 decimals (`round(x, 2)`) so hand-computed
  acceptance literals (e.g. 486.0, 16.8, 57.5, 1500.0) match exactly despite binary float
  noise. This is a display-safe rounding; if downstream combat needs higher precision,
  revisit.
- `ResAmount` has no `.total()`; `army_value` converts to `Res` to sum.
- Thai player-facing strings are copied verbatim from the criteria / construction.py.
